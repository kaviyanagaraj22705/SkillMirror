How SkillMirror works

What it reads, how it scores you, and where your data goes.

The four steps

  1. Read your resume. If you upload a PDF or DOCX, the text is extracted locally. If you paste, we use it as-is.
  2. Read the job description. We pull out the skills it asks for and how strongly it asks for each one: required, preferred, or mentioned.
  3. Match and score. Your resume skills and the job skills are normalized against a dictionary of canonical skills and their aliases, then weighted into a single score.
  4. Build the roadmap. The biggest gaps are turned into a week-by-week plan sized to the hours you have.

How the score works

Each skill the job asks for gets a weight from its importance: required, preferred, or mentioned. Your resume then gets a strength from 0 to 1 for that skill — full credit if you have it, partial credit if you have an adjacent skill, zero if you don't. The score is the weighted average, scaled to 100.

Resume formats

  • PDF — works when the file has a text layer. Scanned image PDFs cannot be read; paste the text instead.
  • DOCX — body paragraphs and tables are read. Text inside headers, footers, and text boxes is not.
  • Paste — the most reliable option, and the one that never leaves anything on disk.

Your data

SkillMirror runs on your machine and has no login. Your resume and the job description are stored in a local SQLite database ({{ settings.DATABASE_PATH.name }}) so you can reopen an analysis later. Uploaded files are parsed in memory and discarded unless KEEP_UPLOADS=true is set.

{% if settings.llm_available %}

Text is sent to OpenRouter for skill extraction and roadmap generation, under the model slug configured for this install. Request bodies are not logged: prompt and document text stay out of the log files.

{% else %}

No OpenRouter key is configured. Analyses run in degraded mode: skills are found by keyword search only, and no roadmap is generated. Set OPENROUTER_API_KEY in .env and restart to enable the full pipeline.

{% endif %}

Delete an analysis from the History page to remove it and its roadmap from the database.

Troubleshooting

“That PDF has no text to read.”
The file is a scan or an image export. Open it in a viewer, copy the text, and paste it into Step 1.
“I couldn't find any skills in that job description.”
Paste the full posting — the requirements section, not just the title. Very short descriptions rarely name enough skills to score.
The roadmap failed but the score is there.
Scoring is deterministic and local; the roadmap needs the LLM. Use Regenerate roadmap on the results page to retry just that stage.
The score looks too low.
Check the resume text for missing sections — a table of skills inside a header or text box is a common cause.
“Rate limit reached.”
Analyses are capped per hour to protect against accidental double-submits. Wait for the window to roll over.
